# atdf2qemu: ATDF + behavior overlays to QEMU tables

Copyright (c) 2026 Clifford Swartz. MIT License (see LICENSE). Open questions kept visible: ATDF data is Apache-2.0
while pp-qemu is GPLv2; GPL obligations when shipping binaries; AI-generated
code.

The generator reads device ATDFs from the DFPs, the per-IP behavior overlays
in `overlays/` and the per-device profiles in `profiles/`. From them it
writes the register tables and device descriptions that the pp-qemu models
and the tools use (spec sections 5.2,
5.3 and 6.1 in `docs/design/v0-vertical-slice.md`). Dependencies: Python 3.10+
standard library and PyYAML.

## Running it

From the project root (use `python3` instead of `py` on Linux/macOS; the
packs live in `~/.mchp_packs`, fetched by `scripts/fetch_packs.py`, and
pp-qemu sits next to this repo):

```
py generator/atdf2qemu.py \
    --atdf ~/.mchp_packs/Microchip/PIC32CM-JH_DFP/1.3.221/PIC32CM-JH01/atdf/PIC32CM5164JH01100.atdf \
    --atdf ~/.mchp_packs/Microchip/PIC32CM-MC_DFP/1.4.67/PIC32CM1216MC00048/atdf/PIC32CM1216MC00048.atdf \
    --qemu-out ../pp-qemu \
    --json-out devices \
    --report "generator/out/report-{device}.md"
```

Always pass every supported device: the per-IP constant headers are merged
over all of them, so generating one device alone rewrites the shared headers
for that device only.

| option | meaning |
|---|---|
| `--atdf FILE` | device ATDF (required, repeatable); the DFP name and version come from the `.pdsc` above it |
| `--overlays DIR` | overlay directory (default `overlays/` of this repo) |
| `--profiles DIR` | device profile directory (default `profiles/`); every device needs `<device>.yaml` |
| `--qemu-out DIR` | pp-qemu source root; C headers are written under it |
| `--json-out DIR` | directory for `<device>.json` |
| `--report FILE` | Markdown provenance report; with several ATDFs the path must contain `{device}` |
| `--check` | write nothing; exit 1 if any output is missing or stale (for CI) |
| `-v` | print informational diagnostics as well as warnings |

The generator writes a file only when its content changes, so QEMU's ninja
does not rebuild unchanged headers. Generated headers in
`include/hw/mchp/gen/` that a run no longer produces are deleted; only files
carrying the `GENERATED by generator/atdf2qemu.py` marker are removed. Exit
codes: 0 = success, 1 = `--check` found stale outputs, 2 = error (bad
overlay, unknown register or field, inconsistent ATDF).

## Outputs

| file | content |
|---|---|
| `pp-qemu/include/hw/mchp/gen/<ip>_<id>.h` | one per IP, shared by every device that has it: `REGn`/`FIELD` constants, value-group constants, view selector constants |
| `pp-qemu/include/hw/mchp/gen/<device>/<ip>_<id>.h` | per device: `MchpRegInfo` tables per view, reset overrides, fuse-loaded resets, the view table for multi-mode IPs |
| `pp-qemu/include/hw/arm/<device>_gen.h` | memory segments, `MchpInstanceInfo` table, NVIC lines and OR-gate sizes, GCLK channel users, DMAC triggers, pad signals |
| `pp-qemu/hw/arm/<device>_nvmrows.h` | `<device>_nvmrows_fill(buf, serial)`: the default 64 KiB NVM rows image (spec 4.3) |
| `pp-qemu/hw/arm/<device>_device.h` | `<device>_device`, the `MchpDeviceInfo` the generic `pic32cm-soc` model is built from (memory map, tables above, CPUID, silicon revisions) |
| `devices/<device>.json` | the same description for tools: memory, instances, IRQs, register maps (offset/size/count/reset/access/masks/flags/fields/provenance), signals, events, NVM rows |
| `generator/out/report-<device>.md` | where every semantic came from (ATDF, overlay or heuristic), conflicts, missing initvals |

`pp-qemu/include/hw/mchp/mchp_device.h` is written by hand, not generated.
It defines `MchpInstanceInfo`, `MchpRegView`, `MchpFuseReset`, `MchpIrqLine`,
`MchpMemSegment`, `MchpSignalInfo`, `MchpPeriphRef`, `MchpSiliconRev` and
`MchpDeviceInfo`.

### Several devices

Devices often share an IP id while differing in details: the JH01 NVMCTRL
has ECC registers the MC00 lacks, MCLK mask bits sit at different positions,
EIC NMIFLAG is 8 bits on one and 16 on the other. The shared constant header
is the merge:

- registers and fields present on any device are defined; a register
  widened on one device gets the wider `REGn`, a field widened at the same
  position gets the wider `FIELD`;
- a field at different bit positions on different devices, or a value name
  that means different numbers (DSU.DID.DEVSEL part codes), is left out, so
  a model that needs it fails to compile instead of being wrong on one
  device;
- a register at different offsets is an error.

Array counts (`_COUNT`) are the largest; models take the real count from
the device's table at run time (`mchp-port` groups, `mchp-gclk` channels).
Devices with different IP ids of the same module (RTC 03608 on the JH01,
U2250 on the MC00) define the same constant names differently, so the
pp-qemu code includes one device's headers per translation unit
(`hw/arm/<device>.c`). `MchpRegInfo` and
`MchpResetOverride` come from `include/hw/misc/mchp_regfile.h` (spec 5.1).

### Generated C names

| what | name |
|---|---|
| register constants (QEMU `registerfields.h`) | `REGn(MCHP_<IP>[_<MODE>]_<REG>, off)` gives `A_...` and `R_...`; `FIELD(..., <FIELD>, shift, len)` gives `R_..._<FIELD>_SHIFT/_LENGTH/_MASK` |
| register-level modes (e.g. BAUD FRAC) | extra `REGn(MCHP_<IP>_<MODE>_<REG>_<REGMODE>, off)` with that layout's fields (as in CMSIS) |
| arrays | `#define MCHP_<...>_<REG>_COUNT n` (stride = size) |
| field values | `#define MCHP_<...>_<REG>_<FIELD>_<VALUE> v` from ATDF value-groups |
| nested groups (PORT) | constants are group-relative: `MCHP_PORT_GROUP_<REG>` plus `MCHP_PORT_GROUP_OFFSET/STRIDE/COUNT` |
| register table | `<device>_<ip>[_<mode>]_regs[]`, `<DEVICE>_<IP>[_<MODE>]_NREGS` |
| register file size | `<DEVICE>_<IP>_REGS_SIZE` (register extent rounded up to 4 bytes; JH01 PORT 0x180, MC00 PORT 0x100) |
| per-element reset exceptions | `<device>_<ip>[_<mode>]_reset_overrides[]`, `<DEVICE>_<...>_NRESET_OVERRIDES` |
| resets loaded from fuses | `<device>_<ip>_reset_from[]`, `<DEVICE>_<IP>_NRESET_FROM` (`MchpFuseReset`) |
| views of multi-mode IPs | `<device>_<ip>_views[]`, `<DEVICE>_<IP>_NVIEWS`, `<DEVICE>_<IP>_DEFAULT_VIEW`; shared: selector `MCHP_<IP>_VIEW_SEL_OFFSET/_SHIFT/_LENGTH`, values `MCHP_<IP>_<SELFIELD>_<MODE>` |
| constants-only groups | DMA/ICM descriptors, CAN message RAM elements, fuse rows: `MCHP_DMAC_DESCRIPTOR_*`, `MCHP_CAN_RXBE_*`, `MCHP_FUSES_USER_WORD_0_*` |
| SoC tables | `<device>_instances[]` + `<DEVICE>_NUM_INSTANCES` + `<DEVICE>_INST_<NAME>` indexes; `<device>_irq_lines[]`; `<device>_mem_segments[]`; `<device>_signals[]`; `<device>_gclk_channels[]`; `<device>_dmac_triggers[]` |

Table entries of a flattened nested group are named `GROUP[g].REG`, e.g.
`GROUP[1].OUTSET`. `alias_of` is resolved within the same group.

## Overlay schema

One file per IP id, `overlays/<ip-lowercase>_<id-lowercase>.yaml`. Facts come
from the datasheet register descriptions. Unknown keys are errors.

```yaml
ip: SERCOM
id: U2201
versions: ["3.1.1"]            # other ATDF versions: warning, overlay ignored
references: ["DS60001632H 30.7 ..."]
modes:                          # or `registers:` for IPs without modes
  USART_INT:
    registers:
      CTRLA:
        pac_protected: true
        enable_protected: {all_except: [SWRST, ENABLE]}
        sync: {SWRST: SWRST, ENABLE: ENABLE}
        self_clearing: [SWRST]
        hooks: [post_write]
reset_overrides: {"GENCTRL[0]": 0x00000106}
reset_from: {CONFIG.PER: USER_FUSES.USER_WORD_0.WDT_PER}
```

| key (per register) | effect on `MchpRegInfo` |
|---|---|
| `w1c: [F..]` or `w1c: all` | `w1c` bits; replaces the ATDF `atomic-op=clear:` guess |
| `ro: [F..]` | bits removed from `wmask` (and from `w1c`) |
| `alias: {storage: R, op: set\|clear\|toggle}` | `MCHP_F_ALIAS_*`, `alias_of` = index of R (may be itself, e.g. INTENSET) |
| `enable_protected: all \| {all_except: [..]} \| [F..]` | `enprot` |
| `sync: {F: BIT}`, `sync: BIT`, `sync: REG.BIT`, `sync: "NAME{n}"` | `syncbusy` mask. The default sync register is `SYNCBUSY`; `REG.BIT` names another one (OSCCTRL `OSC48MSYNCBUSY`, `DPLLSYNCBUSY`). With `{n}`, array element i raises bit `NAMEi`; the table holds element 0's bit and the generator checks that element i uses bit0 << i |
| `write_while_syncbusy: bus_error` | `MCHP_F_BUSY_BUSERR` |
| `strobe: [F..]`, `self_clearing: [F..]` | `rdz` bits |
| `pac_protected: true` | `MCHP_F_PAC` |
| `hooks: [pre_read, post_write]` | `MCHP_F_HOOK_PRE_READ`, `MCHP_F_HOOK_POST_WRITE` |
| `dynamic: true` | `MCHP_F_DYNAMIC` (value from the model's pre_read) |
| `read_only: true`, `write_only: true` | `MCHP_F_READ_ONLY` (`wmask` 0), `MCHP_F_WRITE_ONLY` (`rdz` = impl) |
| `irq_source: {enable: R}` | recorded in JSON/report (IRQ = flag & enable) |
| `note: text` | carried into JSON and the report |
| `optional: true` | the register may be absent on some devices (skipped there); absent registers without it are errors |
| `optional_fields: [F..]` | fields of this register that may be absent on some devices; other unknown field names are errors |

Top-level (or per-mode) keys:

* `reset_overrides`: `REG` patches the table's reset value. `REG[i]` and
  `GROUP[g].REG[i]` produce `MchpResetOverride` entries. Bits outside the
  ATDF bitfields are added to `impl`, with a warning, so they read back.
* `reset_from`: `REG.FIELD: GROUP.REGISTER.FIELD` (or `{fuse: ..., invert:
  true}`) produces `MchpFuseReset` entries. Both sides are checked against the
  ATDF and must have the same width.

## Device profiles

One file per device, `profiles/<device-lowercase>.yaml`, for what belongs
to the device rather than to an IP version. Profile reset overrides replace
the overlay's override of the same register.

```yaml
device: PIC32CM1216MC00048
references: ["DS60001638E Table 8-2 ..."]
silicon_revisions: {A2: 1, A1: 0}     # name: DSU.DID.REVISION; default first
reset_overrides:
  DSU: {DID: 0x11070106}
  NVMCTRL: {PARAM: 0x04030800}
  SUPC: {VREG: 0x00000002}            # data sheet value where the ATDF is wrong
nvm_rows:
  user_row: [0xB15088FF, 0xFFFFF8BB]  # production user row
  serial_addrs: [0x0080A00C, 0x0080A040, 0x0080A044, 0x0080A048]
  serial_default: [0x50500000, 0x00000001, 0x00000002, 0x00000003]
  words:                              # other words, e.g. the calibration row
    - {addr: 0x00806020, value: 0x1103F924, what: "OTP5 word 0 ..."}
```

## Heuristics (no overlay rule for that aspect)

All of these are listed in the report, grouped by rule.

* ATDF `rw="R"` -> `READ_ONLY`; `rw="W"` -> `WRITE_ONLY`, reads 0 (`rdz` = impl).
* Register named `SYNCBUSY` / `*SYNCBUSY` -> `DYNAMIC` (reads 0 in instant sync).
* Writable `SWRST` field -> self-clearing (`rdz`).
* `CMD` field in `CTRLBSET`/`CTRLBCLR` -> self-clearing.
* `atomic-op="clear:<self>"` outside a SET/CLR pair -> all fields W1C.
* `atomic-op="set|clear|toggle:<other>"` -> alias of `<other>` (PORT DIR*/OUT*, ICM IER/IDR).
* `<X>SET`/`<X>CLR` pairs -> aliases with storage `<X>SET` (INTEN*, CHINTEN*, CTRLB*, CLAIM*).
* A lone `atomic-op="set:<self>"` -> write-1-to-set on itself.
* `access=WSYNC/RWSYNC` -> `syncbusy` from SYNCBUSY bits whose names match the
  register's fields, the register name, `<X>` of `<X>SET/CLR`, or `NAME0..` for
  arrays. When nothing matches, a warning is printed.
* impl = union of bitfield masks, or all ones when the ATDF lists no
  bitfields; bits set in the initval are always implemented (PAC STATUSC bit 24).
* Missing initval -> reset 0 (listed in the report).
* The mode `mask` attribute is ignored (SERCOM's `mask="6"`); the mode value is
  compared with the whole selector field.

## Device-level rules

* Instances are sorted by address; core (PPB) and FUSES entries come last and
  are flagged `MCHP_INST_CORE` / `MCHP_INST_FUSES` (not MMIO). PTC is flagged
  `MCHP_INST_NO_REGS`.
* `slot_size` = 0x400, unless the registers extend further (rounded up to a
  power of two: DSU 0x2000, MTB 0x1000) or the memory segment is smaller
  (DIVAS 0x20).
* Alias views come from a second instance register-group with the same layout:
  PORT_IOBUS (0x60000000, 0x200), DIVAS_IOBUS (0x60000200, 0x20), DSU_EXT
  (0x41002100, 0x100, inside the DSU slot).
* IRQs: `irq` is the NVIC line; `irq_input` is the instance's position in the
  ATDF module-instance list of a shared vector (its OR-gate input).
  `<device>_irq_lines[].nsources` gives the OR-gate size.
* The default view of a multi-mode IP is the one selected by the selector's
  reset value: SERCOM USART_EXT, TC COUNT16, RTC MODE0. Instance entries carry
  `views`/`nviews` and `view_sel_offset/_shift/_length`. A generic device can
  therefore switch tables (`mchp_regfile_set_table()`) after a write to the
  selector register, without per-IP code.

## Tests

```
py -m pytest tests/generator -q
```

* `test_atdf.py`: parse counts (55 instances, 37 modules, 32 NVIC lines,
  shared vectors 0/9/10/20/21/22), ids, slots, aliases, signals, modes.
* `test_sercom_usart.py`: the USART_INT table equals the research table in
  `docs/research/microchip-data.md`, which the test parses directly.
* `test_port.py`, `test_resets.py`, `test_heuristics.py`, `test_overlays.py`:
  aliases, PMUX15 and GENCTRL0 overrides, user-row resets, heuristics on TC,
  MTB, ICM and DMAC, the version guard, name errors.
* `test_compile.py`: every header compiles alone, and all headers compile
  together, with `gcc -std=gnu11 -Wall -Wextra -fsyntax-only` against
  `tests/generator/shim/`. The shim's `mchp_regfile.h` holds the spec 5.1
  block verbatim (a test checks this). Its `registerfields.h` restates QEMU's
  REGn/FIELD macros, because QEMU's own header needs `qemu/osdep.h`. Further
  checks in this file: the C `nvmrows_fill()` reproduces the Python image
  byte for byte, and one translation unit compiles in the real pp-qemu
  environment (`qemu/osdep.h`, glib, QEMU warning flags).
* `test_outputs.py`: determinism, 80-column/no-tab/no-`//` style, JSON
  content, `--check`, and that the committed outputs are current.

Environment overrides: `PP_PACKS` (default `~/.mchp_packs`), `PP_ATDF`,
`PP_QEMU_SRC` (pp-qemu source root, default `../pp-qemu`), `PP_GCC` (default `gcc` on PATH; on Windows
`C:/msys64/ucrt64/bin/gcc.exe` first).
