# firmware — done

firmware/hello is written and builds with no warnings (arm-none-eabi-gcc 16.1.0, -Wall -Wextra). Size: text 2604, data 0, bss 1544 (bss includes the 0x200 heap and 0x400 stack). It is built from the unmodified DFP startup and flash linker script plus the DFP and CMSIS 6.1.0 headers. sys_init.c repeats Harmony's SYS_Initialize steps 3-8 exactly; the disassembly matches the boot-path table access for access: same addresses, values, widths, order and unbounded waits, including the calibration-row read (two 32-bit loads at 0x00806024/0x00806020) and the PCHCTRL[22] CHEN read-back wait. After that the image prints:
- a banner
- one line per step, with values read back after init so Harmony's sequence is untouched
- DSU.DID, SCB->CPUID, the 4 serial-number words and the 64-bit calibration row
- one line sent by the SERCOM4_Handler (IRQ13), one byte per DRE interrupt, with a 100 ms SysTick timeout
- 3 LED0 blinks on PC05, active low, timed by polling SysTick COUNTFLAG on the 48 MHz CPU clock
- 'PP:EXIT n', where n is the number of failed self-checks; then it waits for TXC and sits in WFI.

'make check' (check-elf.sh) passes all 11 static checks: vector table at 0x0, SP, reset and IRQ13 vectors, an endless-loop Dummy_Handler, and no BKPT, SVC or semihosting. I also confirmed the checker fails on two deliberately broken images. The twin machine does not exist in pp-qemu yet, so I ran the real ELF on a throwaway Unicorn-based mock in my scratch directory. It reached 'PP:EXIT 0' with the IRQ13 handler entered once per byte, and the transcript is byte-identical to the one in the README. With faults injected (no IRQ, a stalled IRQ print, registers that don't store), the mock showed the documented failure lines and 'PP:EXIT 1'. Nothing has run on the twin or on silicon yet.

## Deviations
- Linking: I used -nostartfiles plus the toolchain's crti.o/crtn.o and --specs=nano.specs, not nosys.specs. newlib-nano provides __libc_init_array, and crti.o/crtn.o provide the _init() it calls. Nothing references a syscall, so nosys is unnecessary. With the default start files, crt0's exit() pulls in stdio and libnosys prints 'not implemented' link warnings, which would break the warning-free requirement.
- The step lines are printed after SYS_Initialize finishes, from registers read back at that point, because the UART only exists after step 7. This keeps Harmony's register sequence exact. The banner comes first, then the step lines, DID, CPUID, serial, calibration row, the IRQ line, the blinks and PP:EXIT. The spec lists the banner after the steps.
- The exit code is the number of failed self-checks: read-backs of steps 4-8 except CAL48M, DSU.DID with the revision bits masked, and completion of the IRQ print. On a correct model and on silicon it is 'PP:EXIT 0', consistent with §5.6 where 0 means pass. CPUID, the serial number, the calibration row and CAL48M are printed but not checked, because they legitimately differ.
- The interrupt-driven print sends one byte per DRE interrupt with no priming loop, unlike Harmony's SERCOM4_USART_Write, so it exercises the NVIC level re-pend once per byte. It is bounded by a 100 ms SysTick timeout so that a broken IRQ path gives 'PP:EXIT 1' rather than a hang. Every other print is polled on DRE.
- Lines end in CRLF.
- Values the DFP doesn't define are local constants with citations: the serial-number addresses 0x0080A00C/40/44/48 (DS60001632H §10.3) and BAUD 63019 (MCC's truncated value).
- I installed unicorn 2.1.4 with 'py -m pip install --user' for the scratch mock. I touched nothing outside firmware/ and my scratch directory.

## Open issues
- Not yet run on the twin (the machine doesn't exist yet) or on silicon (programming needs the user's approval). The mock is not the twin.
- The twin's default NVM rows are the core-QEMU agent's choice. The README transcript uses the design §4.3 example values: serial 0x50500000 0x00000001 0x00000002 0x00000003, and calibration row 0x0000010011040249, which encodes CAL48M 0x00200220, OSC32K CAL 0x40 and ADC bias 0x249. If the generated image differs, update the serial: and calrow: lines (and CAL48M in the step 5 line). All of them are marked as variable in the README, with regexes.
- CPUID: the twin prints 0x410CC200 (QEMU cortex-m0) unless the SoC overrides MIDR. Silicon is expected to print 0x410CC601, but that has not been read from a board.
- The image writes CAL48M from bits 40:19 of the calibration row, like the board's csp_apps example. Current Harmony templates skip that write on PIC32CM JH. If a chip's row field isn't a valid CAL48M, OSC48M could be mistrimmed and VCOM output garbled. Check this on the first silicon run.
- The twin must provide the following, or the image will hang:
- armv7m cpuclk at 48 MHz after step 5. At 4 MHz the blinks take 12x longer (14.4 s); at 0 Hz SysTick never counts.
- The SERCOM4 IRQ level = INTFLAG & INTENSET, with DRE held at 1 while TX is idle, so the NVIC re-pends once per byte.
- NVM rows mapped at 0x00806020 and 0x0080A00C/40/44/48. Otherwise a HardFault lands in Dummy_Handler and the runner times out.
- DSU.DID readable at 0x41002018.
- TXC set after transmit. Without it the image spins in console_flush after PP:EXIT, which runners don't notice.
- objcopy's Intel HEX output contains a type-03 start-address record (entry 0x6A9). MPLAB IPE and pyOCD should accept it, but neither has been tried.
- PowerShell 5.1 mangles embedded double quotes and pipes in 'bash -lc' strings. The README one-liners avoid them; anything more complex should go in a .sh file.
