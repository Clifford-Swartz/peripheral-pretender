# AC (Analog Comparators, IP U2245 1.1.1) on the PIC32CM MC00: research notes

Gathered 2026-10-20 to plan a QEMU model of the AC and a silicon check on the bare EV15N46A, before
any hardware was touched; what that board then answered is in section 7. Sources, most
authoritative first:

1. **PIC32CM MC00 Family Data Sheet DS60001638E** (the PDF from microchip.com, read with
   pdftotext): chapter 38 "Analog Comparators (AC)", 17.5.2 and 17.6.7 (SUPC VREF), 27.7.14 (PORT
   PINCFG), 39.6.8.1 (DAC as an internal reference), Table 43-12 (internal reference), Table 43-30
   (AC electrical, 85 °C) and Table 44-18 (125 °C). Below, "§38.x" means this document.
2. **Errata DS80000905F**, §1.4.1 (AC INTREF).
3. DFP PIC32CM-MC_DFP 1.4.67: `PIC32CM1216MC00048.atdf` (module AC U2245 1.1.1, lines 58-80 and
   1180-1272), `include/component/ac.h`, `include/instance/ac.h`.
4. `devices/pic32cm1216mc00048.json` and pp-qemu's generated `include/hw/mchp/gen/pic32cm1216mc00048/ac_u2245.h`.
5. Harmony CSP `peripheral/ac_u2245` (`config/ac.py`, `templates/plib_ac.c.ftl`, master branch).

Search warning: the Microchip docs MCP returns the **SAM D21** data sheet for the query title "Low-Power,
32-bit Cortex-M0+ MCU with Advanced Analog and PWM". The two documents share that title. Its AC chapter (34) has
a different register map: LPMUX, STATUSC, WINCTRL at 0x0C, SCALER at 0x20 and a second AC1 on "L"
variants. Do not use it for this part. The MC00 HTML is onlinedocs GUID-0D44A543-8D6E-4F72-814C-6F4857061C73.
The search index does not seem to hold its AC chapter, which is why these notes use the PDF.

Twin today: no model. `pic32cm_models[]` in `hw/arm/pic32cm_soc.c` has no AC entry, so the AC is a
plain `mchp-regblock` and STATUSB.READY never sets. Any firmware that polls READY hangs, and
Harmony's `AC_StatusGet()` always returns false.

## 1. Instance facts

| | PIC32CM1216MC00048 (MC00) | PIC32CM5164JH01100 (JH01, same IP 1.1.1) |
|---|---|---|
| Base, IRQ | 0x42005000, IRQ 23 (own line) | 0x42004C00, IRQ 27 |
| Comparators | **2** (COMP0/COMP1, one pair, WIN0). ATDF NUM_CMP 2, PAIRS 1 | 4 (two pairs, WIN0/WIN1) |
| Clocks | APB: MCLK.APBCMASK bit 20, **off at reset** (§38.5). GCLK_AC = PCHCTRL[33], max 48 MHz (FCLK_33) | GCLK 42 |
| PAC | bridge C index 20 (INSTANCE_ID 84), not protected at reset | INSTANCE_ID 83 |
| Event generators | 73 AC_COMP_0, 74 AC_COMP_1, 75 AC_WIN_0 | 72-75 COMP0-3, 76-77 WIN0-1 |
| Event users | 34 AC_SOC_0, 35 AC_SOC_1 (start comparison) | 32-35 |
| AIN pads (function B) | AIN0 PA04, AIN1 PA05, AIN2 PA06, AIN3 PA07 | AIN0-3 PA04-PA07 (COMP0/1). AIN4-7 = PA02, PA03, PB05, PB06 (COMP2/3, same MUX codes 0-3) |
| CMP pads (function H) | CMP0 PA12 or PA18. CMP1 PA13 or PA19 | CMP0 PA12/PA18/PB24 ... CMP3 PA01/PA25/PB31 |
| Sleepwalking | yes (§38.5) | |

On the JH01, AIN4 is PA02, the DAC's VOUT pad, so COMP2/3 also see the DAC through the pad. On
the MC00, PA02 is not an AC input, and the DAC reaches the AC only through MUXNEG = DAC.

The ATDF parameter `COMPCTRL_MUXNEG_OPAMP` (8 on the MC00, 7 on the JH01) has no meaning here. The
field is 3 bits wide and neither part has an OPAMP, so it looks left over from another family. Ignore it.

## 2. Register map (§38.7, ATDF, ac.h)

The register file spans 0x00-0x23. All reset values are 0. "PAC" means the register has the PAC
Write-Protection property.

| Off | Register | Size | Fields (mask) | Sync (SYNCBUSY bit) | Protection / notes |
|---|---|---|---|---|---|
| 0x00 | CTRLA | 8 | SWRST b0 (W, self-clearing), ENABLE b1 (0x03) | SWRST→b0, ENABLE→b1 | PAC. SWRST wins over the rest of the write and resets every register, leaving the AC disabled (§38.7.1). ENABLE=0 stops all comparators but leaves COMPCTRLx.ENABLE set (§38.6.2.3) |
| 0x01 | CTRLB | 8 | START0 b0, START1 b1 (0x03) | none (Property "-") | Strobes that always read 0. STARTx acts only if COMPCTRLx.SINGLE=1 and ENABLE=1, otherwise it is ignored (§38.7.2). Not PAC |
| 0x02 | EVCTRL | 16 | COMPEO0 b0, COMPEO1 b1, WINEO0 b4, COMPEI0 b8, COMPEI1 b9, INVEI0 b12, INVEI1 b13 (0x3313) | none | PAC, **enable-protected** by CTRLA.ENABLE. It is the only register §38.6.2.1 lists |
| 0x04 | INTENCLR | 8 | COMP0 b0, COMP1 b1, WIN0 b4 (0x13) | | PAC, alias of INTENSET |
| 0x05 | INTENSET | 8 | same | | PAC. The DS text "will set the Ready interrupt bit" is a copy error |
| 0x06 | INTFLAG | 8 | same, W1C | | not PAC |
| 0x07 | STATUSA | 8 | STATE0 b0, STATE1 b1, WSTATE0 b5:4 (0 ABOVE, 1 INSIDE, 2 BELOW, 3 reserved) (0x33) | | RO. STATEx is valid only while READYx=1 (§38.7.7) |
| 0x08 | STATUSB | 8 | READY0 b0, READY1 b1 (0x03) | | RO |
| 0x09 | DBGCTRL | 8 | DBGRUN b0 | | PAC. With 0, the AC halts with the CPU and a running comparison completes |
| 0x0A | WINCTRL | 8 | WEN0 b0, WINTSEL0 b2:1 (0 ABOVE, 1 INSIDE, 2 BELOW, 3 OUTSIDE) (0x07) | whole register → b2 | PAC. The DS states no enable protection |
| 0x0C, 0x0D | SCALER0, SCALER1 | 8 | VALUE b5:0 (0x3F) | none | Property "Write-Protected" (read as PAC). **Not** enable-protected: Harmony writes SCALER after enabling the comparator, and `AC_SetVddScalar()` writes it at run time |
| 0x10, 0x14 | COMPCTRL0, COMPCTRL1 | 32 | see below (0x370BF75E) | **only ENABLE** → COMPCTRLx (b3+x). Every other field is "not synchronized" | PAC. Every bit except ENABLE is **locked by the comparator's own ENABLE**, not by CTRLA (§38.7.12 bit 1) |
| 0x20 | SYNCBUSY | 32 | SWRST b0, ENABLE b1, WINCTRL b2, COMPCTRL0 b3, COMPCTRL1 b4 (0x1F) | | RO |

COMPCTRLx fields (§38.7.12). ENABLE is the only field not marked "writable only while ENABLE=0":

| Bits | Field | Values |
|---|---|---|
| 1 | ENABLE | The written value reads back at once. SYNCBUSY.COMPCTRLx stays set until the comparator is actually on or off. Writing 1 locks the other bits until a 0 is written **and synchronized** |
| 2 | SINGLE | 0 continuous, 1 single-shot |
| 4:3 | INTSEL | 0 TOGGLE, 1 RISING, 2 FALLING, 3 EOC (single-shot only) |
| 6 | RUNSTDBY | run in standby (§38.6.13). Unlike the fields that state it, the DS does not say "only while ENABLE=0" here, but the ENABLE text locks all other bits |
| 10:8 | MUXNEG | 0-3 AIN0-3 (written PIN0-3 in the DS), 4 GND, 5 VSCALE, 6 INTREF, 7 DAC |
| 14:12 | MUXPOS | 0-3 AIN0-3, 4 VSCALE, 5-7 reserved |
| 15 | SWAP | swaps the inputs and inverts the output |
| 17:16 | SPEED | 0 LOW (low power), 3 HIGH. 1 and 2 are reserved (ATDF SPEED_LEVELS 2) |
| 19 | HYSTEN | hysteresis on or off. **This part has no HYST level field.** Table 43-30 writes "COMPCTRLx.HYST = 0x1" for this bit. Harmony only emits HYST levels when the ATDF has `HYST_LVL_CONFIG`, which neither the MC00 nor the JH01 does |
| 26:24 | FLEN | 0 OFF, 1 MAJ3 (2 of 3), 2 MAJ5 (3 of 5), 3-7 reserved |
| 29:28 | OUT | 0 OFF, 1 ASYNC (raw output), 2 SYNC (synchronized to CLK_AC, filtered), 3 reserved |

The generated table (`gen/pic32cm1216mc00048/ac_u2245.h`, "No overlay") is wrong or incomplete here:

- COMPCTRL `.syncbusy = 0x2` points at SYNCBUSY.ENABLE. It should be COMPCTRLx (bit 3+x), and for
  the ENABLE bit only.
- CTRLB has no `rdz` (strobe) for START0/1.
- No register has `enprot`. EVCTRL should be enable-protected by CTRLA.ENABLE.
- **COMPCTRL must not get `enable_protected`**: the regfile's `is_enabled` hook checks CTRLA, and
  Harmony's `AC_ChannelSelect()` rewrites COMPCTRL while CTRLA.ENABLE=1. The model must enforce the
  per-comparator lock itself (keep the old bits when the old ENABLE was 1).
- STATUSA and STATUSB need to be dynamic. No PAC flags are set.

## 3. Comparator inputs on this device

| Code | MUXPOS (positive) | MUXNEG (negative) | Meaning |
|---|---|---|---|
| 0 | AIN0 = **PA04** | AIN0 = PA04 | Pad, function B. Also ADC0 AIN4. EV15N46A: Arduino A2 (J803), unconnected |
| 1 | AIN1 = **PA05** | AIN1 = PA05 | ADC0 AIN5. Arduino A3 (J803), unconnected |
| 2 | AIN2 = **PA06** | AIN2 = PA06 | ADC0 AIN6. EV15N46A: **VCOM TX** (SERCOM0 PAD2), keep its mux |
| 3 | AIN3 = **PA07** | AIN3 = PA07 | ADC0 AIN7. EV15N46A: **VCOM RX** (SERCOM0 PAD3), keep its mux |
| 4 | **VSCALE** | GND | Positive: comparator n's own scaler. Negative: 0 V, for zero crossing |
| 5 | reserved | **VSCALE** | comparator n's own scaler |
| 6 | reserved | **INTREF** | bandgap reference at SUPC VREF.SEL: 0 → 1.024 V, 2 → 2.048 V, 3 → 4.096 V. Do not use: erratum below |
| 7 | reserved | **DAC** | DAC output, internal path. §39.6.8.1 says it needs **DAC CTRLB.IOEN**. Internal and external (EOEN) outputs can both be on |

- **VSCALE** (§38.6.5, §38.7.11): `VSCALE = VDD × (VALUE + 1) / 64`, where VDD is VDDANA. The range
  is VDDANA/64 (VALUE 0) to VDDANA (VALUE 63). There is one independent channel per comparator, so
  SCALERn feeds only COMPn. The channel is on only while it is selected (MUXNEG=5 or MUXPOS=4) and
  the comparator is enabled. One step is 78.125 mV at 5.0 V and 51.56 mV at 3.3 V. The MC00 data
  sheet has no scaler INL/DNL/gain figures; the SAM D21 table the MCP returns does, but it is not
  this part. The model must take VDDANA from the board: the desk EV15N46A has VCC_SEL at 5 V, so its
  scaler steps are 52 % larger than at the twin's default 3.3 V.
- **INTREF**: Table 43-12 lists VR_9/11/13 "ACIREF, AC.COMPCTRLn.MUXNEG = INTREF" at 4.096 V
  (3.992-4.164), 2.048 V (1.996-2.082) and 1.024 V (0.998-1.041). Note 4 says the comparator's
  reference must stay within VIN(min)+VIOFF+200 mV and VIN(max)-VIOFF-200 mV. The SUPC chapter
  (§17.6.7 VREF) describes VREFOE only as "routed to an ADC input channel" and does not say whether
  the AC needs it. In the twin's ADC model (silicon-checked), an ADC conversion of INTREF stalls
  without VREFOE.
  **Erratum DS80000905F §1.4.1** (revisions A1 and A2): "do not use the INTREF
  (AC.COMPCTRLx.MUXNEG = INTREF) as an internal reference voltage. Workaround: use the DAC". The
  erratum does not say what goes wrong.
- **Common-mode range** (Table 43-30 CMP_3): GNDANA to VDDANA - 0.5 V. Scaler values above that
  limit (VALUE ≥ 57 at 5 V, ≥ 54 at 3.3 V) give comparisons the DS does not guarantee.
- Pads: §38.6.3 says an AIN pin "must be configured for analog use in the PORT by disabling the
  digital input and output". The input selection should change only while the comparator is
  disabled. §38.6.3 also says "the positive input is one of the external input pins", which
  contradicts MUXPOS = VSCALE; the register description wins.

Twin plumbing: the ADC model's `ain` property ("channel=mV,...") is what the board and the web bench
drive. The bench maps pads to ADC and SDADC channels only (`device_pads()` in
`tools/pp_web/server.py`, lines 83-98). An AC model with the same `ain` property needs one more
case there: `instance == "AC"` and `group == "AIN"` mapped to `("/machine/soc/ac", index)`. The
mikroBUS AN pins (PB08, PA08) are not AC inputs on the MC00, but Arduino A2/A3 are.

## 4. Behaviour

**Enabling** (§38.6.2): a comparator runs only while both CTRLA.ENABLE and COMPCTRLx.ENABLE are set.
Configure COMPCTRLx first. Harmony's `AC_Initialize()` resets the AC, writes all COMPCTRL fields,
ORs in ENABLE with a second write, then writes SCALER, WINCTRL (waiting on SYNCBUSY), EVCTRL and
INTENSET, and sets CTRLA.ENABLE last. `AC_ChannelSelect()` and `AC_SwapInputs()` clear ENABLE,
wait for SYNCBUSY == 0, change the fields and set ENABLE again, all with CTRLA still enabled.

**Start-up and READY** (§38.6.2.4): after enable, a start-up delay ("measured automatically")
passes before the first comparison. Then STATUSA updates, READYx sets, and the comparison raises
its events and interrupts. In continuous mode the delay applies only to the first comparison.
Figure 38-2 shows a further 2-3 GCLK_AC cycles after t_STARTUP. Table 43-30 CMP_19 "Comparator
Enabled to Output Valid" gives 12.7 max at SPEED=0 and 3.8 max at SPEED=3, in "ms". That unit is
almost certainly µs [guess]: the SAM C21 lists 14-22 µs (low power) and 1-2.6 µs (fast) for the
same thing. STATEx is valid only while READYx=1.

**Continuous** (SINGLE=0): the comparator samples at the GCLK_AC rate. Interrupt edges come from
comparing the current sample with the previous one.

**Single-shot** (SINGLE=1, §38.6.2.4.2): the comparator idles. CTRLB.STARTx=1, or an event on
AC_SOC_x with EVCTRL.COMPEIx=1, clears READYx and powers the comparator up. After t_STARTUP it makes
one comparison, updates STATEx, sets READYx, and raises events and interrupts. TOGGLE, RISING and
FALLING compare the result with the previous shot's. EOC sets the flag at the end of every shot.
INVEIx inverts the incoming event. The DS does not say what COMPEI does in continuous mode
[guess: nothing].

**Hysteresis** (§38.6.6): HYSTEN turns it on or off, in continuous mode only. Table 43-30 CMP_5
gives min/max only: **25-161 mV at SPEED=0** and **50-141 mV at SPEED=3**. Table 44-18 (125 °C)
gives 25-179 and 43-145. Nothing says whether the band is symmetric about the threshold.
Offset (CMP_1): ±26 mV (SPEED 0, HYST 0), ±32 (0, 1), ±14 (3, 0), ±16 (3, 1).

**Speed** (§38.6.7): SPEED sets the bias current, which changes start-up and propagation delay.
Small-signal response: 219 ns max at LOW, 65 ns max at HIGH (CMP_15/17, 100 mV overdrive).

**Filter** (§38.6.8): MAJ3 or MAJ5 runs at GCLK_AC, and an output change counts only when N/2+1 of
the last N samples agree. It adds N-1 sample cycles. In continuous mode the first valid output
comes after N samples and then one every cycle; a single shot completes after the Nth sample. The
SYNC pad output includes the filter, ASYNC is the raw comparator. Whether STATUSA.STATE, the
interrupts and the events are filtered is implied but not stated [guess: yes].

**Swap** (§38.6.10): SWAP=1 feeds MUXNEG to the + terminal and MUXPOS to the - terminal and inverts
the output. The logic is unchanged and the offset changes sign, which is what the bit is for.
DS60001638E added the note "the inputs are swapped only if the comparator inputs difference is
within offset values", which is unclear.

**Window** (§38.6.4): WINCTRL.WEN0 pairs COMP0 and COMP1. Both must have the same SINGLE, and the
same RUNSTDBY (§38.6.13). The DS asks for the same pin as positive input on both; the negative
inputs set the limits, either way round. STATUSA.WSTATE0 reads ABOVE, INSIDE or BELOW. WINTSEL
(ABOVE, INSIDE, BELOW, OUTSIDE) selects the condition for INTFLAG.WIN0. The individual outputs,
interrupts and events keep working. In single-shot window mode, either STARTx or either SOC event
starts both comparators. Decode [guess, to be checked by E9]: both STATE=1 gives ABOVE, both 0
gives BELOW, mixed gives INSIDE. That decode works for either orientation, which fits "also works
in the opposite configuration". The DS does not say whether WIN0 sets on entering the region or
while in it.

**Interrupts** (§38.6.11): COMP0 and COMP1 per INTSEL, WIN0 per WINTSEL, one NVIC line (23). The
IRQ is INTFLAG & INTENSET.

**Events out** (§38.6.12): COMPx (generators 73 and 74) is "generated as a copy of the comparator
status", so a level equal to STATEx, while COMPEOx is set. WIN0 (generator 75) is "a copy of the
window inside/outside status" while WINEO0 is set. Both are generated whether or not the interrupt
is enabled. The INTSEL description says "condition for comparator n to generate an interrupt or
event", which conflicts with the level copy (E11). **Events in**: AC_SOC_0/1 (users 34 and 35) start
a comparison (COMPEIx). Several connected events all trigger it.

**Pad outputs** (§38.6.9, OUT): CMPx is on PA12/PA18 (CMP0) and PA13/PA19 (CMP1), PMUX H. OUT is
writable only while ENABLE=0. The CCL sees the comparator only with OUT = ASYNC or SYNC (notes in
§38.6.3 and §38.7.12), which matters for a future CCL model (CCL INSEL AC = 0x5).

**Sleep and debug**: RUNSTDBY, sleepwalking and GCLK_AC on demand (§38.6.13) are not modelled in the
twin (QEMU's WFI). DBGRUN has no effect in QEMU, where a halt freezes virtual time.

**Synchronization** (§38.6.14): CTRLA.SWRST, CTRLA.ENABLE and COMPCTRLn.ENABLE are synchronized
bits, and WINCTRL is a synchronized register. Every other COMPCTRL field is "not synchronized".

### Suggested model (mchp-ac-u2245; suggestions, not facts)

- Add `{ "AC", TYPE_MCHP_AC_U2245, "U2245" }` to `pic32cm_models[]`. The SAM E51's AC is a different
  IP (U2501). Properties, as in the ADC: `ain`, `ain-default` and `vdd` (VDDANA in mV, default
  3300). Count the comparators from `COMPCTRL`'s element count (2 on the MC00, 4 on the JH01).
- Inputs: AINx from `ain`, GND = 0, VSCALE = vdd × (SCALERn + 1) / 64. INTREF comes from the SUPC's
  VREF.SEL (read it as `adc_intref_mv()` does), with whatever VREFOE gating and erratum behaviour
  silicon shows. DAC = the DAC output while it is enabled with CTRLB.IOEN. `mchp_dac_u2214_internal_mv()`
  ignores IOEN today, so it needs an IOEN-aware variant, decided by E5.
- Output: STATE = V+ > V- (with SWAP, V(MUXPOS) ≥ V(MUXNEG)). With HYSTEN in continuous mode, keep
  the previous state and use a band of ±h/2 [guess until E6]. Start with READY set at once, as the
  DAC model does. A virtual-time start-up (and single-shot completion) can follow once E7 has
  measured it.
- When to re-evaluate: on AC register writes, `ain` changes, DAC DATA/CTRLA/CTRLB writes and SUPC
  VREF writes. The DAC and SUPC need to notify the AC, for example through a NotifierList or a GPIO
  line: unlike the ADC, the AC raises interrupts and events on its own. If E4 shows a PORT-driven
  pad reaching the AC, watch pads with `mchp_port_watch()`.
- Wiring follows the `pic32cm_soc.c` naming conventions, which then work with no SoC changes: GPIO
  outputs `comp-event`[n] (level = STATE while COMPEOn is set) and `win-event`[0]; input
  `soc-event-in`[n]; pad outputs `pad-cmp`[n] (STATE while OUT ≠ OFF, -1 when off). The SYNC/ASYNC
  difference is invisible without timing.
- VDDANA has to agree across the ADC, DAC, SDADC and AC. Today each has its own `vdd`, defaulting to
  3300. To compare with the 5 V desk board, pass `-global mchp-adc-u2247.vdd=5000` and the matching
  globals for the others, or add one machine-level `vdd`.

## 5. Silicon test plan (bare EV15N46A, no wiring)

The proposed firmware is `firmware/hello/tests/ac.c` (`make APP=ac BOARD=pic32cm_mc00_cpro`). It
reuses `adc0.h` (adc0_init, adc_read, adc_vddana_mv), `put_field()` and the SysTick (`CPU_CLOCK_HZ`
48 MHz, VAL ticks of 20.8 ns). It prints one line per measurement over VCOM and ends with
`PP:EXIT <fails>`. Print raw trip codes. Fail only where the DS gives a bound; everything else is
information for the model. It must run unchanged on the twin once the model exists.

**Pad rules.** Use PA04 (A2) and PA05 (A3) as AIN0/AIN1; nothing is connected to them. Leave PA06 and
PA07 on SERCOM0 (VCOM). Read the CMP outputs back on **PA18/PA19** (D11/D13, EXT1/EXT2 MOSI/SCK,
which are also the EDBG DGI SPI MOSI/SCK; the EDBG only listens there while PA17, the DGI SS, is
asserted). Leave PA17 alone and run no DGI session during the test. Avoid PA12/PA13: they are the I2C
lines with pull-ups, shared with the EDBG's DGI I2C target at 0x28.

**Setup.** Turn on the APB clocks for AC, DAC, ADC0 and EVSYS. Set GCLK PCHCTRL[33] = GEN0 | CHEN.
Set up the DAC with REFSEL = VDDANA, **IOEN = 1**, EOEN = 1 (J700 stays open) and enable it.
Helpers: `ac_cfg(n, val)` (clear ENABLE, wait for SYNCBUSY, write val, write val | ENABLE, wait for
SYNCBUSY and READY with a timeout) and `ac_state(n)`.
**Order matters**: run E2's VREFOE = 0 cases before anything calls `adc_vddana_mv()`, which sets
VREFOE.

the board (5000).

## 7. Answers from silicon (2026-10-20)

The desk EV15N46A (PIC32CM1216MC00048 rev A1, VCC_SEL at 5 V: VDDANA 4887 mV) ran
`firmware/hello/tests/acprobe.c` and `acprobe2.c`; the model (`hw/misc/mchp_ac_u2245.c` in pp-qemu)
follows these answers, and `firmware/hello/tests/ac.c` checks them on both (silicon transcript:
`golden/pic32cm1216mc00048-a1/ac-silicon.txt`). Numbers by question above:

1. INTREF: the first scaler code above it is 13, 27, 54 for SEL 0, 2, 3, that is 1.02, 2.07 and
   4.12 V at 4.887 V. VREFOE and ONDEMAND do not matter. No sign of erratum 1.4.1 on this part.
2. Scaler: the DAC trip code is within +0 to +2 of round(1023 (v + 1) / 64) across v = 0..63.
3. Hysteresis: about 12-13 DAC codes (60 mV) either side, symmetric, at both speeds; none without
   HYSTEN. COMPCTRL bits 21:20 (in neither the data sheet nor the ATDF) are writable, read back and
   change nothing: four "levels" gave the same trip codes. SWAP leaves the logical result.
4. Timing at 48 MHz, from the enabling write: READY after 358 ticks (7.5 us) at SPEED 0 and 133
   (2.8 us) at SPEED 3; a single shot clears READY at START and sets it after 123-131 ticks
   (2.6 us; 7 us at SPEED 0). SYNCBUSY about 44 ticks after a COMPCTRL write, 33-35 after CTRLA.
5. The DAC input needs IOEN; without it the input reads high (STATE 0 at every code). EOEN is
   irrelevant.
6. A PORT-driven pad (GPIO output, PMUXEN = 0) reaches AIN at full level; pulls on a pad in analog
   mode give floating readings (not modelled).
7. COMPCTRL is locked by its own ENABLE: while set, a write changes only ENABLE (a disabling write
   with new fields keeps the old ones); while clear, a write with ENABLE takes its fields. SCALER and
   WINCTRL are live; EVCTRL ignores writes while CTRLA.ENABLE is set.
8. Window: STATE pair 11 = ABOVE (0), 00 = BELOW (2), mixed = INSIDE (1). WIN0 sets on entering the
   WINTSEL region (OUTSIDE = ABOVE or BELOW), not while staying in it, and never while one comparator
   of the pair is single-shot and the other continuous. The first comparison after enable raises no
   TOGGLE/RISING/FALLING flag; INTSEL EOC flags it once in continuous mode and every shot in
   single-shot mode; a shot that repeats the last result raises no TOGGLE.
9. The COMP event is a level copy of STATE. A start event (COMPEIn) runs one shot per pulse, also
   with INVEI; in continuous mode it does nothing.
10. Disabling clears READY and keeps STATE. SWRST clears everything. One unexplained reading:
    right after re-enabling a comparator that was off for about 30 us, STATUSB read READY = 1 for
    a moment (not modelled).
11. The CMP pad (function H) follows STATE in ASYNC and SYNC mode, and reads 0 with OUT = OFF even
    with the pull-up on.
12. Still open (no JH01 Curiosity Pro on the desk).
