# WDT (U2251) on the PIC32CM1216MC00048: research notes

Gathered for the twin. Sources, most authoritative first: silicon (section 5), the data sheet
(DS60001638E chapter 22), the ATDF and DFP headers, the twin's code (`hw/misc/mchp_sysctrl.c`).

## 1. Instance facts

| | |
|---|---|
| Base | 0x40002000 |
| NVIC line | 1 |
| GCLK channel | none: CLK_WDT_OSC, the 1.024 kHz output of OSCULP32K (OSC32KCTRL) |
| Events | none |
| Pads | none |
| Reset | WDT bit (5) of RSTC.RCAUSE |

| 0x01 | CONFIG | 8 | PER (3:0), WINDOW (7:4); enable-protected; reset from the user row |

| 0x06 | INTFLAG | 8 | EW, write 1 to clear |

## 3. Behaviour (data sheet)

- Normal mode: a time-out of PER (8 << PER cycles, 8 to 16384) resets the system. Writing 0xA5 to
  CLEAR restarts the period; any other value resets at once (22.5.2.4). Early warning (INTFLAG.EW)
  EWOFFSET cycles after the start of the period; never when EWOFFSET is not below PER (22.5.5.2).
- Window mode (WEN): a closed window of WINDOW cycles, then an open window of PER cycles. A clear
  in the closed window resets; the early warning comes at the start of the open window (22.5.2.5).
- Enable protection: CTRLA except ENABLE, CONFIG and EWCTRL only while disabled. Enable-protected
  CTRLA bits can be written with ENABLE = 1, not with ENABLE = 0 (22.5.2.1).
- ALWAYSON: the WDT runs whatever ENABLE says, until a power-on reset. CONFIG and EWCTRL are
  read-only. The data sheet contradicts itself on CTRLA: 22.5.5.1 and the WEN bit description say
  WEN can still be written, the ALWAYSON bit description says CTRLA is read-only.
- Write-synchronized: CTRLA.ENABLE, WEN, ALWAYSON and CLEAR (22.5.4); no timing is given.
- Reserved PER/WINDOW values 0xC–0xF, EWOFFSET 0xB–0xF: no behaviour given.

## 5. Answers from silicon

Two runs on the desk board (EV15N46A), 2026-10-21, transcripts in `build/periph/mc00/`. Times are
from the register write, in microseconds; T is one period of the WDT clock. The desk part's T is
about 997 µs (nominal 976.6 µs at 1.024 kHz): its OSCULP32K runs about 2 % slow. That follows
the part, so the checks allow ±5 %.

1. **Reset values** (E0): CTRLA, CONFIG, EWCTRL 0 on the desk board, whose user row is
   USER_WORD_0 = 0x015000FF, USER_WORD_1 = 0xFFFFF800 (WDT fields all zero). The twin's default
   user row (0xB15088FF, 0xFFFFF8BB) gives CONFIG 0xBB, EWCTRL 0x0B. Tests must not depend on it.
2. **Masks** (E1): CONFIG takes 0xFF (reserved values included), EWCTRL 0x0F. INTENSET/INTENCLR
   bit 0 only. CLEAR reads 0.
3. **Synchronization** (E1, E2): a write that changes ENABLE or WEN sets SYNCBUSY.ENABLE or .WEN;
   a CLEAR write sets SYNCBUSY.CLEAR, also while disabled. CTRLA reads the written value at once.
   A write that changes nothing does not synchronize. Times: 3 T (2982–2996 µs) for a write made
   just after a previous sync finished (in phase with the WDT clock); for a write at a random
   phase, ENABLE and WEN took 3.1–3.8 T and CLEAR 2.5–2.6 T. A second CLEAR while one is busy does
   not stall the bus (5 µs) and does not extend the sync.
4. **Enable protection** (E3): as the data sheet says. While enabled, CONFIG and EWCTRL writes and
   WEN in an ENABLE = 1 write are ignored. A write of ENABLE = 0 cannot change WEN: disabling with
   WEN = 0 leaves WEN set. ENABLE and WEN together from disabled works.
5. **When the count starts** (E4, E5, E12): the early warning comes 2 T + EWOFFSET × T after an
   in-phase enable write, i.e. the count starts one T before the enable sync finishes. A disable
   and re-enable restarts the count (E5: 33.9 ms for 32 cycles, not 11 ms).
6. **A clear** (E4, E6, E7, E12) restarts the count when its sync finishes: the next early warning
   comes EWOFFSET × T after that. CLEAR does not clear INTFLAG.EW.
7. **Time-out** (E8, E9, E14): the reset comes PER × T after the count starts (window mode:
   (WINDOW + PER) × T): 34.5 ms for 32 cycles, 18.9 ms for 16, 66.2 ms for 32 + 32. RCAUSE then
   reads 0x20 (WDT) and CTRLA, CONFIG, EWCTRL reload from the user row. With EWOFFSET beyond PER
   (E9) no early warning comes before the reset.
8. **Wrong key** (E10, E11, E13): resets with RCAUSE 0x20 **also while the WDT is disabled**
   (E10, the data sheet does not say so). The reset comes when the CLEAR sync finishes
   (E11 2.2 ms, E13 2.9 ms) while enabled, about one T later while disabled (E10 3.8 ms). A clear
   in the closed window (E13) resets the same way.
9. **Window mode** (E12): the early warning comes at the start of the open window, WINDOW × T
   after the count starts; EWOFFSET is ignored. A clear in the open window restarts the closed
   window.
10. **Reserved values** (E15, E16): PER 0xC times out after 16.33 s, like 0xB (16384 cycles): the
    reserved values saturate. EWOFFSET 0xB gave no early warning within 900 ms with PER 1024.
11. **Interrupt** (E7): INTFLAG.EW with INTENSET.EW raises NVIC line 1, once per period.

## 6. Open questions

- ALWAYSON (never set on the desk board: only a power-on reset clears it). The model follows the
  data sheet: the WDT runs whatever ENABLE says, ENABLE cannot be cleared, CONFIG and EWCTRL are
  read-only, and WEN can be changed (22.5.5.1 and the WEN bit description, against the ALWAYSON
  bit description).
- Whether a second CLEAR written while the first is busy is dropped or replaces the first (both
  carried the key in E2).
- The phase rules in 3 are fitted to a dozen measurements; the twin's clock has no phase noise,
  so its times sit inside the silicon's spread, not on each sample.
